# 消防器材管理模块

面向园区 / 楼宇安全管理场景的消防器材台账系统：器材全生命周期登记、多条件搜索、CSV 批量导入导出、
附件照片管理，并对**停用、报废等敏感操作强制留痕**。

## 技术栈

- 后端：Node.js + Express 5（REST API）
- 持久化：JSON 文件原子写入（`data/db.json`），零原生依赖，开箱即用
- 附件：multer 本地磁盘存储（`uploads/`，图片白名单 + 10MB 限制）
- 前端：原生 HTML / CSS / JS，深色侧边栏 + 卡片式正式后台风格，无框架依赖

## 启动

```bash
npm install
npm start          # http://localhost:3000
```

首次启动自动写入 10 条演示器材（含停用、报废、超期示例）及对应操作记录。
重置演示数据：停止服务后清空 `data/` 与 `uploads/` 再启动。

## 功能清单

| 需求 | 实现 |
| --- | --- |
| 后台记录 | 器材编号（唯一）、类型、规格型号、楼栋、楼层、位置、检查日期、责任人、状态、备注 |
| 搜索 | 关键词（编号/类型/位置/责任人等）+ 类型、楼栋、楼层、责任人、检查日期区间、状态组合筛选；统计卡片一键筛选 |
| 导入 | CSV 导入（UTF-8 / 兼容 Excel 导出），编号存在则更新、不存在则新增；逐行校验并返回成功/失败明细；提供下载模板 |
| 导出 | 按当前筛选条件导出 CSV（带 BOM，Excel 直接打开不乱码） |
| 附件照片 | 器材详情内点击/拖拽上传（jpg/png/gif/webp/bmp，≤10MB，单次≤9 张），缩略图、大图预览、删除，均写入日志 |
| 停用 / 报废留痕 | 弹窗强制填写**操作原因 + 操作人**；合法状态机 `在用⇄停用→报废`；报废后台账锁定（不可编辑/删除/导入覆盖），报废不可直接启用 |
| 操作记录 | 独立“操作记录”页（按类型/关键词检索）+ 器材详情内时间线，记录前后状态、原因、明细、操作人、时间 |
| 超期提醒 | 检查日期超过 12 个月的「在用」器材自动展示为「超期未检」（不篡改基础状态），可单独筛选导出 |

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/equipment` | 分页 + 多条件查询 + 状态统计 |
| POST | `/api/equipment` | 新增（自动写建档日志） |
| PUT | `/api/equipment/:id` | 编辑（字段差异写入日志） |
| DELETE | `/api/equipment/:id` | 删除（报废态拦截，需填原因） |
| POST | `/api/equipment/:id/transition` | 停用 / 启用 / 报废（原因、操作人必填） |
| GET | `/api/equipment/:id` | 器材详情 + 附件 + 时间线 |
| POST | `/api/equipment/:id/files` | 上传附件照片（multipart） |
| DELETE | `/api/files/:id` | 删除附件 |
| GET/POST | `/api/export` · `/api/import` · `/api/template` | 导出 / 导入 / 模板 |
| GET | `/api/logs` | 操作记录查询（`equipmentId` / `action` / `keyword`） |

## 数据存储

- `data/db.json`：器材、操作记录、附件元数据（写临时文件后 rename，避免写坏）
- `uploads/`：实际上传图片，文件名含器材 ID 与时间戳防覆盖
